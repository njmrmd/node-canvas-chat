## Driving a browser

**Use the harness in this repo. Do not borrow Playwright from another checkout
on the machine, and do not launch a host-installed Chrome with
`channel: "chrome"`.** That is what this project did before, and it made a
result impossible to reproduce on another machine or in CI.

From a cold clone:

```bash
pnpm install
pnpm exec playwright install chromium   # once per machine, ~180 MB
pnpm test:e2e
```

`pnpm test:e2e` boots `next dev` on port 3100 itself and tears it down
afterwards, so there is no server to start first and no port to guess. It needs
no environment variables — the current specs only touch public pages. To drive
a server that is already up, including a Vercel preview:

```bash
E2E_BASE_URL=https://<deployment-url> pnpm test:e2e
```

Specs live in `e2e/`. Read [`e2e/README.md`](e2e/README.md) before adding one —
it covers the selector conventions, the pinned-browser rule, and what to do
with a spec that needs a database.

## Checks before handing work over

```bash
pnpm typecheck && pnpm lint && pnpm test && pnpm build
```

Those four gate CI. `pnpm test:e2e` runs in CI as a separate, non-blocking job.

## Commits

Small, conventional commits. If a change touches auth, key storage or the
provider route, say in the commit or PR description where the key lives, what
encrypts it, and what an attacker with database read access would get.
